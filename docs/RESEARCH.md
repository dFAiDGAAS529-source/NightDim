# Исследование NightDim

## Что показал разбор исходников

### CareUEyes Lite

В `brightness_gamma_control.cpp` яркость ограничена диапазоном 10–100. Для всех трёх каналов строится одинаковая таблица из 256 значений по формуле `i × 255 × brightness / 100`. Контроллер получает DC для дисплеев при перечислении. Он загружает `mscms.dll`, ищет `InternalSetDeviceGammaRamp` через `GetProcAddress` и вызывает экспорт с третьим аргументом `0`. Если экспорт отсутствует, обёртка вызывает публичную `SetDeviceGammaRamp`. Успех оценивается по возвращённому `BOOL`. `RestoreDefault()` снова строит кривую для 100, поэтому предыдущая таблица калибровки не восстанавливается из снимка. [Исходный файл](https://github.com/CareUEyes/careueyes-lite/blob/main/brightness_gamma_control.cpp#L25-L102)

Этот путь объясняет, почему результат Lite нельзя считать ориентиром для публичного GDI-вызова. Семантика внутреннего экспорта не входит в контракт Win32. Исходники Lite распространяются по MIT. Название, логотип и изображения продукта отдельно оговорены в README. [Лицензия](https://github.com/CareUEyes/careueyes-lite/blob/main/LICENSE) · [Условия для визуальных материалов](https://github.com/CareUEyes/careueyes-lite#license)

### Underlit

Проект использует C#, WPF и .NET 8. `UnderlitHost` связывает движок, гамму, окна, системный трей, горячие клавиши и события Windows. Положительная часть шкалы управляет аппаратной яркостью через WMI и DDC/CI. При исчерпании аппаратного диапазона `UnderlitEngine` понижает масштаб LUT с `1.0` до `0.55`. На второй половине программного диапазона появляется чёрный слой с непрозрачностью до `0.88`. Движок также поддерживает анимированные переходы, опрос аппаратной яркости и независимую температуру. [Проект](https://github.com/DietervanDortmont/underlit/blob/main/src/Underlit/Underlit.csproj) · [Хост](https://github.com/DietervanDortmont/underlit/blob/main/src/Underlit/UnderlitHost.cs) · [Движок](https://github.com/DietervanDortmont/underlit/blob/main/src/Underlit/Core/UnderlitEngine.cs)

`GammaRampApplier` открывает DC на каждый GDI-источник и читает исходные таблицы. Запись строит кривую от линейной шкалы, допускается и без снимка. Последующего чтения для подтверждения записи нет. При восстановлении используется исходная или линейная таблица без проверки текущего владельца LUT. `DisplayInfo.StableId` использует имя `\\.\DISPLAYn`, пригодное для открытия DC, но связанное с конфигурацией источников Windows. [Гамма](https://github.com/DietervanDortmont/underlit/blob/main/src/Underlit/Display/GammaRamp.cs) · [Модель дисплея](https://github.com/DietervanDortmont/underlit/blob/main/src/Underlit/Display/DisplayInfo.cs)

`OverlayManager` ведёт по WPF-окну на дисплей. Окно использует `SetWindowPos` в физических пикселях, расширенные стили для пропуска ввода и исключение из захвата. При активном затемнении менеджер каждые 500 мс поднимает окна поверх остальных. В текущем коде хоста штатные сочетания работают через `RegisterHotKey`. Для отключения Windows Night Light есть отдельный параметр с включённым значением по умолчанию. [Менеджер окон](https://github.com/DietervanDortmont/underlit/blob/main/src/Underlit/UI/OverlayManager.cs) · [Окно](https://github.com/DietervanDortmont/underlit/blob/main/src/Underlit/UI/OverlayWindow.xaml.cs) · [Горячие клавиши](https://github.com/DietervanDortmont/underlit/blob/main/src/Underlit/Input/HotkeyManager.cs) · [Настройки](https://github.com/DietervanDortmont/underlit/blob/main/src/Underlit/Settings/AppSettings.cs)

Для NightDim полезны идеи разделения движка и адаптеров, гибридного затемнения, полноэкранного окна на монитор и координат Win32 в пикселях. Собственная реализация нужна для проверки LUT, осторожного восстановления, идентификации дисплеев и событийного управления окнами. Аппаратная ветка, опрос яркости и автоматическое отключение Night Light выходят за рамки MVP. В реализации использованы архитектурные идеи этих проектов. Их код и визуальные материалы не перенесены. Лицензия Underlit проверена по содержимому `LICENSE`. В ней указан `Copyright (c) 2026`. При будущем переносе MIT-кода в копиях и существенных частях нужно сохранить оригинальное уведомление об авторских правах и разрешение из лицензии. [Underlit LICENSE](https://github.com/DietervanDortmont/underlit/blob/main/LICENSE)

### μLumen

`DisplayService` в приложении WPF строит отдельные RGB LUT из параметров цветового профиля, сохраняет исходные GDI-таблицы по дисплеям и содержит экспериментальный DXGI-бэкенд. Код выбирает GDI для оконного режима. Отдельный модуль реализует экранные цветовые матрицы через Magnification API. Обычная монохромная подложка проще и покрывает задачу яркости на рабочем столе, тогда как матрица увеличительного стекла добавила бы ещё один системный механизм со своей областью действия. MIT-лицензия μLumen проверена по файлу репозитория. [Сервис дисплеев](https://github.com/stephenmthomas/lumen/blob/master/Services/DisplayService.cs) · [DXGI-бэкенд](https://github.com/stephenmthomas/lumen/blob/master/DXGIDisplayBackend.cs) · [Описание матриц](https://github.com/stephenmthomas/lumen#-features) · [Лицензия](https://github.com/stephenmthomas/lumen/blob/master/LICENSE)

## Возможности Win32 и решения для MVP

- **Гамма.** Публичная GDI-таблица содержит `3 × 256` значений `WORD` в порядке R, G, B. Microsoft указывает предел отклонения `32768` от тождественной LUT для каждого значения. Для белого `65535` это даёт нижний предел `32767` ещё до учёта остальных эвристик. Windows может отвергнуть кривую с возвратом `TRUE`, а отдельная запись на некоторых устройствах занимает до 200 мс. Сравнение с диагностическим чтением помогает обнаружить отказ или перезапись, но показывает состояние, которое сообщает драйвер. Оно не измеряет светимость и не гарантирует, что таблица достигла дисплея. В HDR поведение GDI-вызова не определено. Windows, ICC-калибратор и другие утилиты могут перезаписать LUT в любой момент. [Using gamma correction](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/using-gamma-correction#background-of-gamma-on-windows) · [SetDeviceGammaRamp](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-setdevicegammaramp) · [GetDeviceGammaRamp](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-getdevicegammaramp)
- **Распределение затемнения.** Умеренную долю преобразования можно отдать принятой GDI-кривой. При отказе или неподтверждённом результате чёрный слой берёт на себя затемнение рабочего стола. Непрозрачность задаётся с шагом `1/255`, поэтому нижние уровни 1–10% могут иметь разные значения alpha. На итоговую читаемость влияют порядок преобразований, глубина цвета, DWM, характеристики панели и её текущая аппаратная яркость. Гамма, температура, фильтр синего и усиления R/G/B требуют управления каналами. Чёрный слой обеспечивает только общее затемнение. [SetLayeredWindowAttributes](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setlayeredwindowattributes) · [Layered Windows](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#layered-windows)
- **Калибровка и восстановление.** Без сохранённой таблицы запись GDI слишком рискованна. Если текущее чтение расходится с последней таблицей NightDim, приложение должно уступить управление и применять доступное затемнение без повторной записи. При сбросе можно восстанавливать снимок только при совпадении текущей LUT с собственной. Сравнение и запись не атомарны, поэтому другой процесс всё ещё может вмешаться между вызовами. Для аварийного восстановления после нового запуска полезна сохранённая пара «исходная таблица и ожидаемая таблица приложения» с привязкой к дисплею. [Ограничения GDI](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-setdevicegammaramp#remarks)
- **HDR и топология.** `QueryDisplayConfig` сопоставляет активные источники и цели. `DisplayConfigGetDeviceInfo` возвращает путь интерфейса монитора и параметры Advanced Color. Путь устройства подходит для привязки настроек в пределах установки Windows, но может поменяться при смене порта или переустановке устройства. При клонировании несколько физических целей могут получать один источник изображения, поэтому индивидуальная коррекция на стороне оконного приложения ограничена общей поверхностью рабочего стола. [QueryDisplayConfig](https://learn.microsoft.com/en-us/windows/desktop/api/winuser/nf-winuser-querydisplayconfig) · [DisplayConfigGetDeviceInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-displayconfiggetdeviceinfo) · [Путь монитора](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-displayconfig_target_device_name) · [Advanced Color](https://learn.microsoft.com/en-us/windows/win32/direct3darticles/high-dynamic-range)
- **DXGI и DDC/CI.** `IDXGIOutput::SetGammaControl` действует в полноэкранном режиме приложения и потому не покрывает системный рабочий стол. Monitor Configuration API посылает монитору аппаратные команды DDC/CI. Этот путь зависит от дисплея и не реализует требуемый программный диапазон. [Using gamma correction](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/using-gamma-correction) · [Monitor Configuration](https://learn.microsoft.com/en-us/windows/win32/monitor/monitor-configuration)
- **Ввод и DPI.** Для `WS_EX_LAYERED` стиль `WS_EX_TRANSPARENT` передаёт мышь окнам под слоем. `WS_EX_NOACTIVATE` и позиционирование с `SWP_NOACTIVATE` сохраняют фокус. `WS_EX_TOOLWINDOW` убирает окно из панели задач и Alt+Tab. Координаты `rcMonitor` и `SetWindowPos` в Per-Monitor V2 позволяют покрыть весь монитор, включая конфигурации с отрицательными координатами. Порядок окон остаётся ограничением для других topmost-окон, эксклюзивного полного экрана и защищённого рабочего стола. [Window Features](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features#layered-windows) · [Extended Window Styles](https://learn.microsoft.com/en-us/windows/win32/winmsg/extended-window-styles) · [Per-Monitor DPI](https://learn.microsoft.com/en-us/windows/win32/hidpi/high-dpi-desktop-application-development-on-windows)
- **Скриншоты.** `WDA_EXCLUDEFROMCAPTURE` применим к собственному верхнеуровневому окну в DWM. Это запрос на исключение в поддерживающих его путях захвата. Результат вызова не заменяет проверку конкретного клиента захвата, например «Ножниц» или программы записи. [SetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity)

## Выбранная шкала

NightDim отображает пользовательскую яркость `b` на относительный цифровой коэффициент `(b / 100)^0.60`. Если драйвер подтверждает LUT, коэффициент LUT по яркости ограничен снизу значением `0.80`, а остаток задаёт overlay. В режиме Overlay слой использует полный коэффициент. Такое преобразование оставляет больше цифровых градаций на нижнем конце шкалы, чем прямое отображение 1% в alpha, и не задаёт физическую яркость панели. Цветовая кривая дополнительно ограничивается по читаемости и диапазону GDI.

На одном SDR-конвейере пробная запись LUT при 96% подтвердилась чтением, исходная LUT восстановилась. В режиме Overlay измерены цифровые значения белого образца 64, 42 и 16 для 10%, 5% и 1%. Этот тест подтверждает различимость цифровых ступеней. Оптическую проверку проводят отдельно. [Результаты и условия замеров](ACCEPTANCE.md)
