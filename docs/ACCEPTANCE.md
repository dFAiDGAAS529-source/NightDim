# Приёмка NightDim

## NightDim 1.1.1

- 28 тестов ядра проверяют в том числе неизменную шкалу фиксированного затемнения, безопасный переход с LUT на слой и блокировку двойного затемнения при неподтверждённом состоянии LUT.
- Стенд WPF проверяет, что одинаковые настройки дисплея не отправляются повторно в бэкенд, а после смены режима, геометрии или восстановления результат пересчитывается. В обоих языках проверены переключатель режима, доступность ползунка яркости и временная блокировка цветовых регуляторов.
- Смена яркости конкретного монитора при переходе между вкладками физически не проверялась. Отклик панели на содержимое проверяется отдельно с закрытым NightDim.

## NightDim 1.1.0

- 24 теста ядра проверяют обработку LUT, восстановление и загрузку сохранённого языка. Старые настройки без поля языка открываются по-русски.
- Стенд WPF проверяет переключение RU → EN → RU, подписи ВКЛ/ВЫКЛ и ON/OFF, состояние переключателя автозапуска и доступность основных действий при 100%, 125%, 150% и 200%.
- Тихая установка и удаление проверены в изолированной папке. Версия 1.1.0 появилась в списке установленных приложений, ярлык меню «Пуск» вёл к установленному EXE, хэши 474 файлов совпали. Удаление очистило тестовую папку, регистрацию приложения и ярлык.
- Фактический повторный вход в Windows для проверки автозапуска не выполнялся. Установщик не подписан Authenticode.

## Midnight Glass

Редизайн проверен в живом Windows 11-сеансе с тремя SDR-выходами. Для проверки использован отдельный каталог настроек. Сравнение SHA-256 подтвердило совпадение 15 файлов движка, бэкендов дисплеев, обработки горячих клавиш и рабочего потока с версией до редизайна.

| Сценарий | Результат |
| --- | --- |
| Release win-x64 | Self-contained публикация и сборка решения прошли. Все 24 теста движка прошли |
| Интерфейс и профили | В живом окне «Вечер» установил 40% и 4500 K со статусом Hybrid. Ручная установка гаммы 1,15 подсветила «Свой». Стенд проверил все семь слайдеров и все четыре сегмента |
| Мониторы и сохранение | Список показал три дисплея. После выбора второго его яркость была 100% при 40% на первом. Переключатель синхронизации и сохранение профиля записали выбранные 98% в изолированный файл |
| Точный ввод | При фокусе на ползунке стрелка изменила яркость со 100% до 99%, одно деление колёсика — с 99% до 98%. Видимое кольцо фокуса осталось на ползунке |
| Безопасный предпросмотр | В живом окне на втором дисплее 10% вернулись к 100% без подтверждения. Во время предпросмотра 1% Ctrl+Alt+F10 отключила эффекты и вернула прежнее значение. Стенд проверил доступность кнопок и блокировку редактирования при 1%, 5% и 10% |
| DPI | WPF-стенд применил 100%, 125%, 150% и 200% к фактическому дереву интерфейса. При 200% в низком окне регуляторы доступны прокруткой, подтверждение и отмена находятся вне прокрутки. Дополнительно проверен рабочий размер 1366 × 768 при 200% |
| Автоматическая высота | В финальной сборке при раскрытии тонкой настройки окно поднялось до верхней координаты 103 px. Нижний край окна оказался на 1025 px, выше панели задач. Все RGB-регуляторы, статус и команды остались видны |
| Выход | Штатная команда «Выйти из NightDim» закрыла окно. После выхода журнал восстановления тестового экземпляра был пуст |
| Жёлтая рамка | Полоса на основном дисплее обнаружена до создания overlay. Границы окна затемнения совпали с границами каждого из трёх выходов. [Данные проверки и шаги воспроизведения](OVERLAY-DIAGNOSTICS.md) |

[Скриншоты запущенного NightDim и снимки WPF-стенда](../artifacts/ui-screenshots/). Чтобы повторить WPF-проверку, выполните `dotnet run --project tests/NightDim.UiChecks -c Release -- artifacts/ui-screenshots`.

**NOT TESTED на оборудовании:** физическая читаемость при 1–10%, переход между дисплеями с разным системным масштабом, HDR, горячее подключение, сон и пробуждение, эксклюзивный полноэкранный режим. Снимки WPF при разных DPI проверяют разметку и видимость команд.

## Замеры базовой версии

Windows 11 x64, build 26200, .NET 10.0.12. Win32 перечислил три расширенных SDR-выхода 1920 × 1080 с координатами X = −1920, 0 и 1920. Значения из запуска опубликованного EXE с `--probe`, проверки интерфейса и отдельного нативного smoke-теста.

| Проверка | Фактический результат |
| --- | --- |
| Конфигурация Release | WPF-сборка и self-contained публикация win-x64 прошли без ошибок |
| Unit-тесты | 24 из 24. Включены LUT, диапазоны, нейтральный режим, профили и настройки, отказ backend, конфликты и восстановление |
| Обнаружение дисплеев | Найдены три дисплея, исходная LUT прочитана на всех. Повторное перечисление заняло 0,35 мс |
| Gamma на основном SDR | Применение программной яркости 96% с контрольным чтением заняло 13,18 мс. Восстановление исходной LUT подтверждено за 1,98 мс |
| Границы overlay | Скрытые окна получили точные координаты всех трёх экранов, включая отрицательный X |
| Overlay на основном SDR | При alpha=3 окно было видимым. Прозрачность подтвердилась чтением, affinity вернул `0x11`, расширенные стили — `0x080800A8`. Создание и чтение заняли 5,25 мс |
| Win32 hit-test и фокус | При alpha=3 `WindowFromPoint` вернул прежнее окно под слоем, foreground HWND сохранился. После снятия overlay его HWND уничтожен |
| Захват GDI | На собственном белом тестовом окне `BitBlt(SRCCOPY \| CAPTUREBLT)` вернул исходный пиксель с `WDA_EXCLUDEFROMCAPTURE`. С affinity NONE пиксель стал темнее по каждому каналу, после удаления overlay вернул исходное значение |
| Инициализация хоста | 403,74 мс до завершения инициализации в трее |
| Покой в трее, нейтральный режим | За 5,01 с счётчик процессорного времени приложения не вырос. Working set 140,0 МиБ, private bytes 84,2 МиБ |
| Интерфейс, защитный откат | При 10% в обычном сеансе показаны Hybrid, обратный отсчёт и кнопка подтверждения. Без подтверждения значение вернулось к 100%, статус — к нейтральному режиму |
| Аварийная клавиша | В обычном сеансе при 50% и Hybrid комбинация Ctrl+Alt+F10 перевела приложение в «Отключено». После возврата параметра к 100% Ctrl+Alt+F9 включила нейтральный режим |
| Восстановление после завершения процесса | Тестовый экземпляр завершился при активном Hybrid. Отдельный запуск того же кода восстановления сравнил текущую LUT с журналом, точно восстановил исходную LUT и удалил запись |

Замер отклика относится к операции backend, к которой при перемещении ползунка добавляется debounce 110 мс. Замер покоя охватывает процесс NightDim. Нагрузка DWM и GPU отдельно не измерялась. Результаты readback описывают состояние API. Оптическая яркость, бэндинг и читаемость требуют ручной проверки.

### Нижний диапазон в композиторе

Overlay применили к основному SDR-выходу поверх собственной тестовой области 48 × 48 пикселей. Gamma оставили исходной, исключение из захвата временно сняли для замера. В таблице показаны считанные через `BitBlt(SRCCOPY | CAPTUREBLT)` 8-битные значения. Каналы R, G, B совпали для каждого образца.

| Положение ползунка | Alpha | Белый образец | Серый образец |
| --- | ---: | ---: | ---: |
| 100% | 0 | 255 | 128 |
| 50% | 87 | 168 | 84 |
| 10% | 191 | 64 | 32 |
| 5% | 213 | 42 | 21 |
| 1% | 239 | 16 | 8 |
| Возврат к 100% | 0 | 255 | 128 |

Этот замер подтверждает разные цифровые уровни и возврат к исходному кадру для одного SDR-конвейера. Физическая светимость и пригодность для чтения остаются частью ручной приёмки.

## Ручная проверка на физическом мониторе

Перед запуском закройте экземпляр NightDim из трея, если он уже работает. Откройте [публикацию](../artifacts/NightDim-win-x64/NightDim.exe). Оставьте синхронизацию выключенной и выберите один тестовый монитор. Откройте настройки и убедитесь, что указана действующая комбинация восстановления. Откройте на этом экране страницу с обычным текстом, тонкими линиями и градациями серого. Сохраните комфортную аппаратную яркость монитора на всё время проверки.

| № | Действия и критерий | Результат физической проверки |
| --- | --- | --- |
| 1 | С нейтральным цветом установите 100%, 50%, 10%, 5%, 1%. На каждом новом минимуме 1–10% прочитайте окно проверки и нажмите «Оставить», только если экран различим. Проверьте заметную разницу между 10%, 5% и 1% | NOT TESTED |
| 2 | Верните 100% через ползунок. С нейтральным цветом сравните изображение с исходным и убедитесь, что статус больше не показывает Overlay или Hybrid | NOT TESTED |
| 3 | В темноте прочитайте мелкий текст при 10%, 5% и 1%. Проверьте тени, градации и цветные элементы. Запишите самый низкий пригодный уровень и тип дисплея | NOT TESTED |
| 4 | На совместимом SDR при 100% измените температуру 6500 → 3200 K, затем гамму 1,00 → 1,30. Проверьте, что обе настройки видны одновременно. Верните их отдельно. Повторите для ослабления синего и одного коэффициента RGB | NOT TESTED |
| 5 | При видимом overlay нажмите кнопку в окне другого приложения, прокрутите содержимое, введите текст и проверьте Alt+Tab. Снимите тот же экран Ножницами и средством записи экрана, сравните с контрольным кадром при выключенном эффекте | NOT TESTED |
| 6 | При выключенной синхронизации выставьте разные параметры на двух дисплеях. Включите и выключите синхронизацию. Подключите и отключите второй монитор, смените основной и разрешение. Проверьте восстановление настроек и границы слоя | NOT TESTED |
| 7 | При обычном уровне отправьте компьютер в сон и разбудите. Проверьте список экранов и обычные настройки. Для уровня 1–10% проверьте запрос новой проверки после пробуждения | NOT TESTED |
| 8 | Установите разные масштабы (например, 100% и 150%), расположите второй монитор слева от основного. Проверьте отсутствие полос по краям и выходов за границы | NOT TESTED |
| 9 | Переключите совместимый выход из SDR в HDR и обратно. Проверьте яркость через Overlay и статус недоступной цветовой коррекции в HDR | NOT TESTED |
| 10 | При 5% дождитесь отката без подтверждения. Повторите с зарегистрированной аварийной клавишей, затем с командой трея. Проверьте штатный выход и перезапуск с сохранённым экстремальным значением | NOT TESTED |

Для проверки конфликтов измените LUT известным инструментом при активном NightDim и вызовите следующее обновление NightDim. Ожидается переход на overlay без перезаписи чужой кривой. Для проверки аварийного сценария сначала сохраните контрольную LUT и используйте умеренную яркость. После завершения процесса проверьте, что окно исчезло, затем перезапустите NightDim и сравните LUT. Оба сценария на физическом мониторе имеют статус **NOT TESTED**.
